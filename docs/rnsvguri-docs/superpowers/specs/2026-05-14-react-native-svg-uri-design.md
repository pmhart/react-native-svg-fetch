# react-native-svg-uri — Design Spec

**Date:** 2026-05-14
**Status:** Awaiting implementation

---

## Overview

A React Native npm package that fetches SVG files from remote URLs, cleans them for compatibility with `react-native-svg`, caches the result, and renders them as a drop-in component. Supports optional file system persistence, color theming, and graceful fallback states.

---

## Architecture

Four modules with a single responsibility each, orchestrated by the component:

```
react-native-svg-uri/
├── src/
│   ├── fetcher.ts       # HTTP fetch → raw SVG XML string
│   ├── fixer.ts         # raw XML → cleaned, render-ready XML
│   ├── cache.ts         # in-memory Map + optional file system
│   ├── SvgUri.tsx       # component — orchestrates the three above
│   └── index.ts         # public exports
├── example/             # generated by create-react-native-library
├── package.json
├── tsconfig.json
└── README.md
```

| Module | Input | Output | External deps |
|---|---|---|---|
| `fetcher` | URL string | Raw SVG XML string | none (`fetch` built-in) |
| `fixer` | Raw XML, optional color | Cleaned XML | none |
| `cache` | URL + color cache key | Cached XML or null | optional: expo-file-system or react-native-fs |
| `SvgUri` | props | Rendered component | react-native-svg |

## Component API

```tsx
<SvgUri
  // required
  uri="https://example.com/icon.svg"
  width={64}
  height={64}

  // optional — replaces all fill/stroke colors with currentColor
  color="#E63946"

  // optional — shown while fetching (auto-generated grey box if omitted)
  placeholder={<MyShimmer />}

  // optional — shown on fetch/parse failure (defaults to placeholder)
  fallback={<Image source={require('./icon-fallback.png')} />}

  // optional — persist to file system across app sessions
  persistCache={true}

  // optional — applied to the wrapping View
  style={styles.icon}
/>
```

**TypeScript interface:**

```ts
interface SvgUriProps {
  uri: string
  width: number | string
  height: number | string
  color?: string
  placeholder?: React.ReactNode
  fallback?: React.ReactNode
  persistCache?: boolean
  style?: StyleProp<ViewStyle>
}
```

### Global configuration

For apps that always want file system caching, call once at startup:

```ts
import { configureSvgUri } from 'react-native-svg-uri'
configureSvgUri({ persistCache: true })
```

Individual component instances can override with their own `persistCache` prop. Document this prominently in README.

## Loading States & Data Flow

```
mount with uri + color
        │
        ▼
  in-memory cache hit (uri::color)? ──yes──▶ render SVG immediately
        │no
        ▼
  persistCache enabled? ──yes──▶ file system cache hit? ──yes──▶ apply color
        │                                │no                        │
        │no                              │                          ▼
        └────────────────────────────────┘              store in memory cache
        ▼                                                           │
  show placeholder                                                  ▼
  (user-provided → auto grey box)                          render SVG
  fetch SVG in background
        │
        ├──success──▶ run fixer ──▶ write to caches ──▶ render SVG
        │
        └──failure──▶ show fallback (→ placeholder → auto grey box)
```

**Fallback cascade:** `fallback` → `placeholder` → auto-generated grey box at requested size.

## SVG Fixer Pipeline

Two distinct steps in `fixer.ts`:

**Step A — clean (runs once per URL, output is what gets cached):**
1. Strip unsafe/unsupported elements: `<script>`, `<style>`, `<animate>`, `<animateTransform>`, `<animateMotion>`, `<foreignObject>`
2. Remove `width` and `height` from the root `<svg>` element — `SvgXml` handles sizing via its own props
3. Ensure `viewBox` is present: derive from original `width`/`height` if missing; log a warning and proceed if neither exist

**Step B — colorize (runs after cache load, when `color` prop is provided):**
4. Replace all `fill` and `stroke` attribute values with `currentColor`, skipping `none`, `transparent`, `inherit`, and `currentColor`. Also handle inline `style="fill: red"` patterns via regex.

## Cache Strategy

Two-layer cache:

| Layer | Key | Value | Persistence |
|---|---|---|---|
| In-memory Map (module scope) | `${uri}::${color\|\|''}` | Render-ready XML (color applied) | App session only |
| File system (optional) | `base64(uri).svg` in app cache dir | Cleaned XML with original colors | Across restarts |

**Why two different values:**
- File system stores the cleaned-but-not-colored version so any future color can be applied without re-fetching
- In-memory stores the color-applied version for instant re-renders

**File system adapter:** at runtime, try `require('expo-file-system')` then `require('react-native-fs')`. Use whichever resolves. If neither is found and `persistCache` is `true`, throw a descriptive error directing the user to install one of the two.

**Cache directory:** use the OS-managed app cache directory (`FileSystem.cacheDirectory` on Expo, `RNFS.CachesDirectoryPath` on bare RN). The OS may evict these under storage pressure, which is acceptable — the library will re-fetch transparently.

## Package Tooling

- **Scaffold:** `npx create-react-native-library@latest react-native-svg-uri`
- **Build:** react-native-builder-bob (generated by the scaffold)
- **Language:** TypeScript
- **Peer dependencies:** `react`, `react-native`, `react-native-svg >=12`
- **Optional peer dependencies:** `expo-file-system`, `react-native-fs`
- **Tests:** Jest + `@testing-library/react-native` for the component; plain unit tests for `fixer` and `cache`
- **CI:** GitHub Actions (generated by scaffold)
- **Publish target:** npm as `react-native-svg-uri`

---

## Out of Scope for v1

- Multi-color selective replacement (only a single `color` prop, nuclear replacement)
- Custom cache adapters / public cache interface
- SVG animation support
- Server-side rendering
- Web platform support
